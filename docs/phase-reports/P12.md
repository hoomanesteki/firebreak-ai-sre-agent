# Phase 12: Website, documentation, release

## Summary

The phase whose job was to publish eleven phases of work, and whose main finding is that the
honest version of the front page has no numbers on it.

Every eval report in this repository is marked `quotable_as_a_result: false`. So
`build_site_stats.py` publishes five stated absences rather than five figures, each carrying the
reason from its own report, and the site and README say plainly that nothing on them is a result.
Two figures in `reports/eval/` look quotable and are not, a synthetic-fixture run at 1.000
root-cause accuracy and a partly recorded tuning split at 0.143, and the build refuses to publish
either. A test injects 1.000 into a template and watches the suite fail.

**The most useful thing built here is the class of check that catches documentation and
interface rot.** Three test files now assert that every command, path, module and config key the
Makefile and the docs name actually exists. Writing them found four real defects, one of which
had been broken for an entire phase while 34 tests reported it working.

**The second is `make verify-clean`.** `make verify` runs against this working tree and CI runs
against a fresh clone, and everything git-ignored is the difference. Two "green here, red there"
failures in one phase were enough to build the thing that catches them before a push.

## What was built

**`scripts/build_site_stats.py`** (`make site-stats`), the only thing allowed to put a number on
a public surface. A metric becomes a number only if its report says so; otherwise the `value` is
null and the reason takes its place, so a template has nothing numeric to print even if a page
asked. It also checks report staleness against the bundles on disk, and refuses to publish from a
report whose recorded count no longer matches.

**The site** (`site/build.py`, seven templates, `make site`). Home, How it works, Evaluation,
Self-improvement, Security, Decisions, Run it. Numbers come only from the stats file through one
macro. `StrictUndefined` plus a metric getter that raises means a missing key fails the build,
which is SPEC.md Section 15's rule rather than a preference. No scripts, no external stylesheets,
no fonts fetched, no images: diagrams are inline SVG. The Decisions page is generated from the
ADR files, so an ADR cannot be written and left off.

**`.github/workflows/site.yml`**, Pages deployment on pushes to main touching `site/`, `reports/`
or `docs/`. It checks the stats file is current and the README matches it *before* building, and
runs the anti-leak tests as a pipeline step, because publishing a wrong number is not a crash.

**`docs/runbook.md`**, the seven procedures from Section 16. Each says how to tell it worked and
what to do when it did not. The retune procedure keeps the worked example of a change that was
refused, because the reasoning generalises.

**`docs/demo-shot-list.md`**, eight scenes with two marked unrecordable and why. The proof scene
records the Evaluation page as it actually is rather than being skipped, and the narrator is told
not to speak a number that is not on the screen.

**`docs/release-notes-v1.0.0.md`**, a draft. Not tagged: a tag is a public statement and the
archive it points at is the owner's to publish.

**`make verify-clean`** (`scripts/verify_clean_clone.py`), which clones the current commit into a
temporary directory, installs from the lock file with `FIREBREAK_`, `LLM_` and `VIRTUAL_ENV`
stripped, and runs CI's steps in CI's order under CI's names. It prints what it does not cover
every time.

**Three contract test files** for the documented interface: `test_makefile_targets_resolve.py`,
`test_docs_references_resolve.py`, `test_web_serve.py`, plus `test_console_serves.py` which starts
a real server, and `test_eval_report_selection.py`.

## Defects found in earlier phases while building this

Four, and each is the same shape: something the documentation promised that nothing tested.

**`make console` was broken for the whole of Phase 11.** It ran `python -m firebreak.web.serve`
and no such module existed. All 34 Console page tests passed, because they drive the application
object through `TestClient`, which never opens a socket. Fixed: the entry point exists, binds
loopback because the Console renders incident telemetry and has no authentication, and refuses a
port that is not a port. One integration test now starts the process and requests pages over the
wire. `uvicorn` moved from the `dev` group to the dependencies, since an install without dev
groups had the pages and no way to serve them.

**Eval reports were ordered by modification time.** Git rewrites mtime on every checkout, usually
stamping every file identically, so the ordering reflected what the working tree last did. This
was not theoretical: reverting the fix and running the test shows the fixture run at 1.000
root-cause accuracy being promoted over the recorded run at 0.143. The Evaluation page would have
claimed perfect accuracy on recorded incidents with nothing in the repository having changed.
Ordering is now by the report's own `generated_at`.

**The README promised `make demo-local`**, which was never built, and its stats block had eaten
the newline after its own end marker. Both found by the new docs test.

**`reports/lab/recording_progress.json` overstates by three.** It lists 11 recordings where 8
exist; three were deleted for recording corruption and never un-marked. The recorder is
unaffected, because `already_recorded` reads the filesystem and its docstring says why, but the
file is the one a person would trust. Left as-is and recorded, because correcting it would erase
the only record of the corruption incident. The owner's call.

**`make demo` could not run on a fresh clone, which is the criterion that names it.** It went
straight at the live stack, so with no Docker it failed with a Compose error about a missing
submodule, and a first-time reader learned nothing about Firebreak from that. It now chooses
between the live stack and the offline showcase, prints both conditions before choosing, and says
what would have changed the choice. The thing it must not do is run the lesser path quietly: the
offline showcase names 8 of 8 faults where the same triage scores 1 of 7 on recordings, so a
reader who does not know which ran takes away a figure six times too good.

**Six phase reports had no "Deviations from the spec" section.** P01 to P06, against a template
in SPEC.md Section 21.1 that requires one. An absent section is ambiguous between "this phase
deviated nowhere" and "nobody asked", and the reviewer reads the report rather than asking. The
conformance check now asserts every template heading is present in every completed phase's
report.

The six sections were added with a statement that nothing was reconstructed, because nothing
could be: whether those phases deviated is not documented, and inventing a list eleven phases
later would be worse than recording that the question went unanswered.

**`make ci-status` answered for one workflow and was read as answering for all of them.** Found
the first time two workflows ran on one commit, which was this phase's own push to main. It took
the newest run for the SHA, so a green `site` deployment finishing after a red `ci` run would have
reported the commit as passing. It now reports every workflow by name and fails if any of them
failed, with seven tests including the exact shape of the miss. This is the third defect in this
one tool, which is the pattern worth noting: the thing that tells you whether everything else is
fine is the thing nobody checks.

**The coverage floor was 84.5%, not 85%, for every phase of this project.** Found by noticing
that `make test` exited 0 while printing "FAIL Required test coverage of 85.0% not reached. Total
coverage: 84.97%". Both halves of that are correct and they come from different code:
pytest-cov's summary line compares the total plainly, while the exit code goes through
coverage.py's `should_fail_under`, which is `round(total, precision) < fail_under`. The default
precision is zero, so 84.97 rounds to 85 and the gate passes.

So the enforced floor has always had a half-point of slack, and a log line said FAIL while the
build went green. `precision = 2` is now set in `[tool.coverage.report]`, which makes the message
and the exit code agree and the floor exact. This does not invalidate any earlier phase's "verify
passed", since nothing was ever below 84.5, but it does mean the number in those reports was
measured against a looser gate than the one they name.

## Defects found in this phase's own work

**Twice, a test passed locally and failed in CI.** Both times the cause was the same: a
comparison that included data derived from the eight bundles on my machine, which CI does not
have. The first fix was to exclude the key. The second was to make the mistake impossible:
`build()` now returns nothing machine-dependent, `local_diagnostics()` is separate, and a test
asserts `build()` is identical with and without bundles. A comment would have needed the next
comparison to remember it.

**`make verify-clean` failed its own first run in two ways.** It leaked `VIRTUAL_ENV` into the
clone, so uv warned and used the parent's environment. And initialising the submodule fetched the
whole OpenTelemetry Demo over the network, which took minutes and then died with a reset
connection. It now strips the local variables and copies the pinned checkout instead, after
checking it is at its recorded pin, because copying a drifted submodule would hide the drift
those tests exist to catch.

**The docs test flagged "make it harder" and "make load levels hard" as make targets.** A test
that cries wolf on English gets loosened until it checks nothing, so it now matches only where
`make` is written as a command.

## Deviations from the spec

**No result of any kind, and the site says so on every relevant page.** SPEC.md Section 15 asks
for three result cards on the home page, a calibration curve and risk-coverage charts. The cards
exist and read "not measured" with the reason. The charts are not built, because a chart of
nothing is worse than a sentence saying there is nothing.

**No resume bullets.** The spec asks for them generated from `site_stats.json`. Generating a
bullet from a file whose every metric is an absence would produce either a false claim or a
description of mechanisms, and the second is the owner's to write.

**No tag.** Drafted notes instead.

**The site is seven pages of prose about a system with no measured performance.** That is the
honest shape of this release and it is worth naming as a deviation, because SPEC.md Section 15
was written expecting numbers.

## Known issues

**The front page is uncomfortable to read and correct.** A visitor sees four cards saying "not
measured". The alternative was publishing a fixture figure, and this repository contains one that
would read as 100% accuracy. The discomfort is the right trade and it is still a cost.

**Nothing prevents a person reading a stale report as current.** The build refuses to publish
from one, and the Console shows when each report was generated, but the file itself does not know
it has been superseded.

**`make verify-clean` is not CI.** It cannot run the Neo4j integration tests or the dependency
audit, and it says so every run. A machine with no submodule checked out gets a warning rather
than a fetch.

**The site deployed on the first attempt.** `site.yml` ran when this phase merged to main, with
its build and deploy jobs both green, so the workflow is no longer untested-on-first-use. It is
what surfaced the `ci-status` defect above, since that was the first commit with two workflows.
