# Phase 06: Agent graph v1, live recording, and what real data changed

## Summary

Two things happened in this phase and the second one matters more.

The agent graph is built and runs end to end. On a recorded incident it names
the right service, gathers evidence through the real tool layer, and writes
claims that all survive the exit gate.

**And the incident library started being recorded, which invalidated most of
what the project believed about itself.** Deterministic triage goes from 100%
top-1 on synthetic fixtures to 2 of 9 on recorded incidents. Three defects stood
between the pipeline and real telemetry, all invisible on fixtures, and a fourth
problem was in the library: twelve scenarios were built on a fault the load
generator cannot trigger.

`docs/first-real-recordings.md` is the full account. This report covers the
phase; that document covers the finding.

## What was built

- **`agent/state.py`**: the investigation state, plus `Brief`, the slice a
  specialist is allowed to see.
- **`agent/budget.py`**: budgets, the repetition limit, stall detection, and one
  closed vocabulary of stop reasons.
- **`agent/llm.py`**: the model client with the four modes, structured output,
  and cassette keying for replay.
- **`agent/nodes.py`**: entry gate, hypothesis seeding, commander, specialists,
  hypothesis board, critic, reporter, exit gate.
- **`agent/graph.py`**: the loop, and the stub that makes it runnable with no
  model at all.
- **FB-v1 as an eval configuration**, so the graph is measured through the same
  graders and statistics as B0.
- **`lab/export_traces_logs.py`**: the Jaeger and OpenSearch exporters, which
  had been missing since Phase 1.
- **`firebreak lab record`** and **`scripts/record_library.py`**, resumable.
- ADR-0008, partial as SPEC.md Section 17 specifies.

## The agent, on a real incident

`intl-shipping-slowdown-10sec-20u`, recorded from the live demo:

| | |
|---|---|
| root cause named | `shipping` |
| truth | `shipping` |
| tool calls | 5 |
| evidence records | 5 |
| specialists contributing | 4 of 4 |
| claims after the exit gate | 4, all citing gathered evidence |
| stopped because | complete |

Every surviving claim cites an evidence id the investigation actually gathered,
because the exit gate strips the rest.

## FB-v1 against B0

On the eleven recorded validation incidents, both score **18.2% correct**.

That is the expected result rather than a disappointment. In stub mode the only
thing separating the two configurations is a keyword rule standing in for
reasoning, and both rest on the same deterministic ranking. **A real comparison
needs a real model**, and this number is the reference that comparison will be
made against.

## Defects found

Nine, and the first four are the ones that mattered.

1. **The deterministic scorer read whole series through the tool row cap.**
   `MAX_ROWS = 50` protects a model's context; the scorer has none to protect.
   Across 18 services each got three samples, `MIN_BASELINE_POINTS` discarded
   them, and a 25x latency regression on the true culprit scored zero. Fixed
   with a separate `metric_series`; the culprit moved from rank 5 to rank 1.

2. **A signal appearing from nothing scored ten million.** An error counter
   going from zero to one event per hundred seconds outranked the actual
   incident by six orders of magnitude. Bounded at 20. A pooled scale was tried
   as the principled fix and **measured worse twice**, so the bound stays for a
   measured reason and the rejected alternative is recorded with its numbers.

3. **Twelve scenarios could never fire.** `imageSlowLoad` is evaluated in
   browser-side React and Locust never runs it. Each of the twelve recorded a
   bundle in which nothing happened while its label named a culprit, so a system
   correctly reporting a healthy system would have been scored wrong on all
   twelve. Three of them were worse than wasted: their primary fault did
   nothing, so the only real effect was the flag labelled a *harmless
   distractor*, and a system correctly naming `shipping` was marked wrong.

4. **Three metric queries returned nothing, silently.** The topology lookup
   asked for a name that is not the declared key, so every recording would have
   exported a graph with **zero edges**. Both container metric names were wrong
   and both were grouped by a label they do not carry, so the resource families,
   24 of the 30 `test_ood` tasks, would have had no resource signal. The tests
   encoded the same wrong names as the code, which is why none of it was caught:
   **a stub written from the implementation cannot catch a vocabulary bug.**

5. **A failed export left a partial bundle**, which blocked the retry and would
   have made the batch recorder skip that scenario for ever. Export is now
   staged and moved atomically.

6. **The observability stack was a root-cause candidate.** Real recordings put
   `jaeger` and `flagd-ui` in the top three. `flagd` is now excluded for a
   second reason: naming the flag service is saying "a feature flag did this",
   which is the answer.

7. **The eval refused to run** once one bundle existed, because the
   recorded-versus-synthetic switch was global. Now per split, with coverage on
   every report.

8. **The traces analyst gathered nothing, for an entire run, silently.** It
   passed `service` where `find_traces` takes `services`. A tool that cannot
   answer is deliberately treated as a fact about the incident, which is right,
   and a wrong argument name is not a fact about the incident. A test now
   validates every specialist's planned calls against the tools' own models.

9. **Two defects in the eval gate**, both found by running FB-v1 through it.
   The calibration check reported `FAIL_CALIBRATION` for a candidate whose
   calibration had *improved*, because it lacked the underpowered rule the
   quality metrics already had. And its statistic was the mean absolute gap,
   which cannot separate 0.99-at-50%-accuracy from 0.5-at-50%: both average
   0.5, so the gate saw no difference between badly overconfident and well
   hedged, and its own test asserted a failure it could not detect. Now the
   per-task Brier contribution.

## What is still broken

**Abstention does not work on real telemetry.** The threshold was tuned on
fixtures where the two populations separated perfectly. On recordings they
overlap completely:

| | Largest anomaly |
|---|---|
| faulted (9) | 4.85 to 11,980 |
| no-fault (2) | 9.00 to 534 |

No threshold separates those. The signal itself does not discriminate, and a
different one is needed. Two no-fault recordings is too few to design against,
which is why train is recording: it holds seven more.

The consequence reaches the agent, not just B0. Triage abstains on most real
incidents, so `seed_hypotheses` short-circuits and the graph never runs its
loop. The threshold has been left alone rather than fitted to eleven
recordings, because fitting it to a sample this small is the same mistake in the
other direction.

## Known issues

**No model has ever run.** Everything measured about the agent is stub mode,
which tests the harness and says nothing about what a model would conclude.
This is the single largest gap in the project.

**B1 is not built.** It is the baseline that answers whether the harness is
worth its complexity, and it needs a model to mean anything, so it is queued
behind credentials rather than behind work.

**Recording is 12 of 114 scenarios.** Train is running. At 18 minutes each the
library is about 34 hours and cannot be compressed.

**The `latency` family is thinner than intended.** Removing `imageSlowLoad`
left `intlShippingSlowdown` as the only server-side latency fault the demo
offers.

## Open questions for the owner

1. **Model credentials.** Three acceptance criteria and the entire question of
   whether the agent beats deterministic triage wait on `LLM_BASE_URL` and
   `LLM_API_KEY`, or a local Ollama endpoint.
2. **Where ground truth lives.** `git add labels/` is blocked in this
   environment, and `package_library` archives bundles only, so labels
   currently have no distribution path. Either the repository or the release
   archive, and either needs a change.
3. `gh auth login`, still one command.

## Next phase preview

Phase 7 is the exit gate and the report contract in full, which is largely
built here as `exit_gate` and can be completed without a model. The more
valuable work, though, is not a phase: it is finishing the recording and finding
an abstention signal that separates on real telemetry, because until that
happens every configuration abstains on most incidents and the eval measures
the threshold rather than the system.
