# Phase 00: Repository foundation

## Summary

The repository now has a working Python 3.12 toolchain, the rules that keep
every later phase honest, and the checks that enforce them. Nothing about
the product is built yet, which is intentional: Phase 0 exists so that the
first line of product code lands in a repository that already rejects
invented numbers, AI attribution, and sloppy prose.

## What was built

- `SPEC.md`, the contract for all 12 phases, committed verbatim apart from
  the deviations listed below.
- `pyproject.toml` with Python 3.12 pinned, Ruff, mypy strict on `src` and
  `scripts`, pytest with an 85% coverage floor, and a `firebreak` console
  script.
- `scripts/check_repo_hygiene.py`: five rules from SPEC.md Section 19.4,
  covering banned characters, filler words, AI attribution in commit
  messages, commit authors, and a README stats block that has to match the
  generated report.
- `scripts/hooks/check_commit_msg.py`: Conventional Commits with the scope
  list from SPEC.md Section 18.3, a 72 character subject limit, imperative
  mood, and the same character and attribution rules.
- 61 tests over both scripts and over `settings.py`.
- `src/firebreak/settings.py`: validated environment configuration that
  refuses invalid log levels and malformed base URLs, and fails fast when
  API mode is selected without credentials.
- `Makefile` with `setup`, `verify`, `lint`, `types`, `test`, `hygiene`.
- `.pre-commit-config.yaml` wiring Ruff, the hygiene script, the commit
  message hook, the standard pre-commit hooks, and gitleaks.
- `.github/workflows/ci.yml` with a verify job and a security job
  (`pip-audit`, gitleaks), plus the PR and phase issue templates.
- `CLAUDE.md` and `AGENTS.md` with the working rules, and
  `.claude/settings.json`, which blanks commit and PR attribution and denies
  reads of `labels/` and `.env`.
- `docs/adr/0001-agent-framework.md` and the ADR index.

## Deviations from the spec

1. **Repository name.** SPEC.md Section 1 named the repository
   `firebreak-ai-sre`. The existing repository is
   `firebreak-ai-sre-agent`. The committed SPEC.md uses the real name.
2. **License.** SPEC.md Section 17 asks for Apache-2.0. The repository
   already carries MIT, committed by the owner. MIT was kept rather than
   changed unilaterally. See open questions.
3. **Dependency set.** Only the packages Phase 0 needs are installed.
   LangGraph, OpenTelemetry, DuckDB, Neo4j, and the rest arrive in the
   phase that uses them, so the lock file stays reviewable and API
   confirmation happens close to the code that depends on it.
4. **macOS workaround in `make setup`.** Every `.pth` file written into the
   virtual environment on this machine carries the macOS hidden flag, and
   CPython's `site` module skips hidden `.pth` files, so the editable
   install never reached `sys.path`. `make setup` clears the flag on Darwin
   only, and pytest is configured with `pythonpath = ["src"]` so the test
   suite does not depend on the editable install at all.
5. **ADR-0001 sources.** SPEC.md reference R20 is a community blog post.
   The ADR cites the AutoGen repository notice and LangChain's own
   comparison page instead, which are closer to the source.
6. **SPEC.md Section 20 condensed.** The spec embedded copies of
   `CLAUDE.md` and `.claude/settings.json`. The committed SPEC.md points at
   the real files instead, so the two cannot drift apart. Reference R14 had
   a mangled benchmark name, written out as "tau-bench".

## Open questions for the owner

1. **`gh` is not authenticated.** It was installed during Phase 1 but not
   logged in. It is needed for pull requests, milestones,
   branch protection, and the eval gate PR comments in Phase 8. Install it
   with `brew install gh && gh auth login`, or say that pull requests will
   be opened in the web UI and the milestones created by hand.
2. **License.** Keep MIT, or switch to Apache-2.0 as SPEC.md Section 17
   says? Apache-2.0 adds an explicit patent grant, which is the usual
   reason to prefer it. This is a one-line change either way.
3. **Machine capacity for Phase 1.** This machine has 16 GB of RAM and 10
   cores. The OpenTelemetry Demo is documented as needing roughly 6 GB, so
   it should fit, but recording about 120 incidents takes hours of wall
   clock time. Confirm the demo library gets recorded here, or on a cloud
   VM as SPEC.md Section 23 suggests.
