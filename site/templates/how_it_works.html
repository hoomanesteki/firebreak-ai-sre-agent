How it works

A frozen recording of an incident goes in. A report whose every claim re-runs to the same bytes comes out, or an abstention. Between those, four things do the work: deterministic triage, typed tools that record their own provenance, a commander with specialists and an independent critic, and a gate that removes claims rather than warning about them.

The shape of one investigation

Deterministic triage first

Before a model sees anything, Firebreak computes robust anomaly scores over every service's metrics, using a median and median absolute deviation rather than a mean and standard deviation, because one spike moves a mean and a fault is a spike. It walks the service graph with personalised PageRank to separate a broken service from the services merely downstream of it, and produces a ranked shortlist.

If nothing scores above the abstention threshold, the investigation ends there and says so, naming the largest deviation it found and the threshold it was compared against. A reader can disagree with the threshold, which is the property that makes the answer useful.

Typed tools, not free-form queries

Tools take validated arguments and build their own queries. A model never writes a query string. That costs flexibility and buys three things the project depends on: a query nobody can inject into, a cap on how much data one call can return, and an evidence record whose identifier is a hash of what the call was and what came back.

Every call records its query, its time window, a fingerprint of the backend it hit, and a hash of its rows. That record is what a claim cites, and it is what the gate re-runs.

Roles

RoleDoesCannot
Commander Chooses which hypothesis to test next and which specialist to send. Call an evidence tool itself.
Metrics, logs, traces and change analysts Gather evidence on one hypothesis with one question each. See each other's answers, so four specialists are four independent looks.
Critic Argues against the leading hypothesis on the same evidence. Gather new evidence, so it cannot build its own case.
Reporter Writes claims, each naming the evidence it rests on. Cite a record no tool produced.

The exit gate

Six checks run on the finished report. They remove claims rather than annotating them, because a warning next to a claim is a claim that still gets quoted.

CheckRefuses
coverageA claim citing an evidence id nothing recorded.
re_executionA citation that does not re-run to the same hash.
numbersA number in prose that its cited evidence does not contain.
consistencyA report that disagrees with the notebook or the timeline.
confidence_sanityHigh confidence the evidence does not support.
abstentionNaming a service whose support is below the threshold.
What the gate does not check. Whether a claim says anything. Six checks ask whether a claim is supported; none asks whether it is informative, and a report of true, cited, uninformative sentences passes cleanly. This showed up in the offline demo's own transcripts and is recorded as an open question rather than quietly fixed.

Harness principles

PrincipleWhy
The agent never sees a label Ground truth lives outside the bundles, in a package only the eval code may import, enforced by a test that walks the import graph. Each label carries a random canary and every prompt is scanned for it.
Bundles are frozen Replay is byte-stable, so a change in a score is a change in the code.
Fault flags are hidden from the change log Otherwise the answer is in the evidence.
Tuning uses train and validation only Held-out splits are computed once per release candidate, or not quoted.
Two test splits, not one In-distribution asks whether it works; out-of-distribution holds back whole fault families and asks whether it generalised or memorised.

The decision records give the alternatives each of these rejected.
