Why a figure that exists is still not a result

reports/eval/ holds eight reports and not one of them is quotable. Each says so in its own file, under quotable_as_a_result, with the reason attached. Three kinds of reason come up, and the difference between them matters:

ReasonWhat the figure actually measures
Synthetic fixtures Bundles generated from a spec rather than recorded from a running system. Useful for building the harness and nothing else. The largest single finding in this project is that fixtures are a different scale of difficulty from recordings rather than merely an easier one: the same deterministic triage scores far higher on fixtures than on real recordings of the same faults.
Partly recorded split A real measurement of a small sample. Eight of sixteen validation scenarios are recorded, so the figure is true about those eight and says nothing about the split.
Tuning split How well the system fits data it was developed against. Thresholds and prompts were chosen using validation, so a validation figure measures fit, not performance.
A report can also go stale, and that is worse than a missing one. A report is a snapshot. One in this repository was computed over a single recorded incident that was later deleted for recording corruption, so it describes a state that no longer exists while still satisfying "every number traces to a report". The build checks a report's recorded count against the bundles present and refuses to publish from one that no longer matches.

Graders

GraderAsksDoes not apply when
root_causeIs the named service the injected one, at rank 1.The incident has no fault, so there is nothing to name.
root_cause_top3Is it anywhere in the top three.As above.
abstentionDid it abstain exactly when it should have.Never. This is the grader for the no-fault cases.
fault_classIs the mechanism right, not just the service.No fault.
onsetHow far off is the stated start time.A bundle with no measurable flag convergence.
evidence_validityDoes every citation re-run to the same bytes.Never. It applies to abstentions too.
remediationWould the proposal have fixed it.No proposal was made.

Two graders rather than one for the naming question, because a single grader scoring both identification and abstention would let a system that abstains everywhere look like one that identifies everything. A no-fault task is not applicable to the root-cause grader, and that is reported rather than counted as a pass.

How a claim is checked

Accuracy is reported with a bootstrap confidence interval, not as a bare number, because a figure over eight scenarios and a figure over eighty are not the same kind of statement. Comparisons between configurations are paired by incident and use a paired bootstrap, so the interval reflects the same incidents being compared rather than two independent samples. A configuration is only accepted over its baseline when the interval excludes zero.

Baselines and ablations

ConfigurationIs
b0Deterministic triage alone, no model. The floor any agent has to beat.
b1A single-agent ReAct loop with the same tools.
b2The same loop without the knowledge graph.
fb-v1The full system.
a1 to a6Ablations, each removing one component to see what it was worth.

b0 is the important one. A multi-agent system that cannot beat a page of statistics is a multi-agent system that should not exist, and the comparison is reported whichever way it comes out.
