An AI SRE that cites evidence you can re-run

Firebreak investigates a production incident, names a root cause or says it cannot, and links every sentence in its report to the query, time window and rows it rests on. If a claim cannot be re-executed to the same bytes, a gate removes it before anybody reads it.

The problem

The expensive part of an incident is not the fix, it is the minutes spent deciding which of forty services to look at. That decision is made from dashboards under time pressure, and the reasoning behind it is usually lost by the time the postmortem is written.

An agent that guesses faster does not help, because a confident wrong service costs more than no answer. So the design question Firebreak is built around is not how to answer more often. It is how to make an answer checkable, and how to say nothing when the evidence will not support saying something.

What it does

Deterministic first
Robust anomaly scores and a ranked service list before any model runs, so the model starts from a shortlist rather than from the whole system.
Evidence or nothing
Every tool call records the query, window, backend fingerprint and a hash of its rows. A claim keeps its citation or it does not ship.
An exit gate that removes claims
Six checks, including re-running every citation and refusing a confidence the evidence does not carry. Failing them removes the claim rather than warning about it.
Abstention as a first-class answer
On a healthy system it says so and stops. Naming a service when nothing is broken is the worst failure this design admits.

Quickstart

Runs on a clone with no model, no Docker and no network:

cd firebreak-ai-sre-agent
make setup
make demo-offline   # {{ showcase.incidents }} incidents, replayed and checked against their recordings
make console        # the Console on http://127.0.0.1:8080

Run it covers local models, the live stack and recording new scenarios.
